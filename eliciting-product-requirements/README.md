# eliciting-product-requirements

将模糊的业务需求，通过结构化多轮对话，逐步转化为可落地的 Spec、RFC 和 UI 蓝图。

## 如何触发

在AI对话中直接描述你的业务需求即可，示例 prompt：

```
帮我梳理一下「订单退款」功能的需求
```

```
我想做一个员工请假审批系统，帮我从需求分析开始
```

```
我们需要给现有系统加一个优惠券模块，帮我出 Spec
```

## 工作流程 & 产出物

| 阶段 | 做什么 | 产出物 |
|---|---|---|
| Phase 1 | 7 维度 MECE 深度挖掘 | 需求分析报告 + 澄清问题清单 |
| Phase 2 | 基于 DDD 的规格设计 | Spec（含 FR 编号 + 验收标准）+ RFC（领域模型） |
| Phase 3 | 质量校验 + 用户确认 | Checklist 自检 + 授权请求 ⚠️ **必须确认后才进入下一阶段** |
| Phase 4 | 页面与交互设计 | UI 蓝图（路由、数据绑定、交互约束） |

## 注意事项

- 阶段严格顺序执行，**不会跳过或合并**。
- Phase 3 是硬性检查点——未确认前不会进入 UI 设计或编码。
- 每个阶段结束后会停下来等你回复，不会一口气跑完。
